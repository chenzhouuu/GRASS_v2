## Report Structure

Generate Python code that creates a PDF with the following sections:

1. **Executive Summary** — Key findings and recommendations (1 paragraph).
2. **Data Overview** — What was queried, scope, data sources, limitations.
3. **Analysis & Findings** — Detailed results backed by evidence and numbers.
4. **Visualizations** — If chart PNGs exist, embed them with `pdf.image()`.
   Provide an interpretation paragraph for each chart.
5. **Optimization Results** — If applicable, present the solution and business
   implications.  Skip this section if no optimization was performed.
6. **Recommendations** — 3-5 specific, actionable next steps.
7. **Appendix** — Cypher queries used, methodology notes, raw data summaries.

## PDF Generation Rules

- Use `from fpdf import FPDF`.
- Page size: Letter.  Margins: 20 mm.
- Title page with report title, date, and "GRASS Supply Chain Analytics".
- Use `pdf.set_font("Helvetica", ...)` — do NOT use Times or any TTF font.
- Section headers: Helvetica Bold 14pt.  Body: Helvetica 10pt.
- Embed PNG charts with `pdf.image(path, w=170)` — check the file exists first.
- Save the PDF to `{report_path}` and **print the path** so it can be extracted.
- Print exactly: `REPORT_PATH: {report_path}`
- Handle long text with `pdf.multi_cell(0, 6, text)`.
- Add page numbers in the footer.

## CRITICAL Python String Rules
- **NEVER** put text with apostrophes or single quotes inside `'...'` strings.
- **ALWAYS** use double-quoted strings (`"..."`) for ALL text passed to
  `pdf.cell()`, `pdf.multi_cell()`, and `pdf.text()`.
- For text containing both quote types, use triple-double-quotes (`"""..."""`)
  or escape with backslash.
- Build long text in variables first, then pass the variable to `multi_cell()`.
- Example: `text = "Lancaster County's dairy sector"` then `pdf.multi_cell(0, 6, text)`

## Style Guidelines

- Lead with business implications, support with data.
- Use supply chain terminology appropriately.
- Be specific: use exact numbers from the results.
- Include caveats and limitations.
- Write for decision-makers, not data scientists.
